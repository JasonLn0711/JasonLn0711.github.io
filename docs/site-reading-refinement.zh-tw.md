# 正式站閱讀與研究導覽優化

2026-11-24 的走查以 `cs-kairos.com` 與 `origin/main`（`90de6ba`）為基準。首訪讀者要找值得讀的文章，研究訪客要快速找到可公開查核的證據。延續暖白底色、人物照片、現有內容分區和 SvelteKit 靜態輸出。

Jason 指定以走查結果規劃改版，並決定公開頁面優先呈現讀者採取行動或判斷證據所需的資訊。本紀錄承接[首頁設計沿革](site-v3-design-source.zh-tw.md)，由[發布手冊](deployment-runbook.md)連到正式站驗收。個人主站擁有文章、研究與作品入口，[Kairos Learning](https://learn.cs-kairos.com/)擁有課程與互動教材。

| 問題 | 設計決策 | 驗收 |
| --- | --- | --- |

Rust 剖析未找到值得移植的熱點，這一輪使用現有靜態 HTML、Svelte 與 CSS 實作。正式發布與真實讀者驗收各有獨立的證據。

## 本機驗收

- 22 項測試、Svelte 檢查、靜態建置與 62 個 HTML 頁面的發布前檢查均通過。
- Chrome 走查涵蓋 320 × 320 的選單捲動與鍵盤焦點、繁中首頁與工作坊語言切換、手機目錄與研究證據錨點，也重測停用 JavaScript 時的選單與目錄。Safari 的 320 × 390 預覽同時顯示七個選單項目。
- 獨立雙語測試頁驗證了同一網址的中文與英文段落跳轉。公開建置使用正式文章來源。
- 升級前的 390px／2× 手機比較在本機預覽分別測得 393,270 與 126,545 位元組。瀏覽器選用的頭像由 269,994 降至 4,962 位元組。

## 發布前的相依更新

既有 npm 高風險稽核要求 SvelteKit 3.1.1。此次將 SvelteKit、靜態 adapter 與相容的 TypeScript 更新放在獨立提交，並保留 npm lockfile、既有 CI 檢查及 Cloudflare 靜態設定。從相同網站內容產出的 62 個 HTML 路徑一致。61 個預先產生的頁面通過文字、連結、語言與中繼資料比對。RSS、sitemap、robots、重新導向與標頭檔位元組相同。 [SvelteKit 3 遷移說明](https://svelte.dev/docs/kit/migrating-to-sveltekit-3)
